# 统一记忆与长期叙事

LightRP 继续使用同一个 D1 事件／来源／不可变记忆版本引擎。剧情线与叙事归档是新的记录类型，复用分支、知情授权、版本、纠正、遗忘和删除检查；没有引入第二个记忆服务。

## 状态归属

| 层               | 唯一维护内容                               | 不承担的职责                             |
| ---------------- | ------------------------------------------ | ---------------------------------------- |
| 事件与来源       | 已提交原文、获取证据、作者操作             | 不把生成草稿或摘要再提交为剧情           |
| 绑定资料与规则   | 角色卡、世界书、作者更正                   | 历史归档不建立新的规则权威               |
| 事实／关系／认知 | 客观时态状态、定向获知和误信               | 不从章节封存推断知情                     |
| 剧情线           | 承诺、目标、谜团、伏笔、冲突及明确完成条件 | 不因未提及、转场、章节结束自动结案       |
| 经历／方法／能力 | 实际尝试、成功证据、使用反馈、适用前提     | 目标完成不等于技能成功或获得能力         |
| 归档             | 固定来源的局部摘要及场景→剧情段→章节       | 引用规范化版本，不裁决当前事实或技能状态 |
| 检索与上下文     | 合法候选、证据展开、预算与去重             | 不新增知识、经历或成功计数               |

在线回合沿用一次验证过的抽取快照。事实、授权、经历及剧情线共用这份快照，然后处理局部归档和索引。`narrative_extractions` 标记完整在线来源，归档只摘要它们；长开篇／历史原文按片段使用同一抽取契约，摘要与共享结构化结果来自同一次调用。父归档与局部重建只总结原文或固定子版本，不能反向学习。历史事实的幂等键包含内容与证据，避免同一个长事件的不同片段误用抽取数组序号。

新在线回合在剧情提交事务内声明冻结抽取对来源的处理职责，后台稍后消费该快照；归档不能在这段间隙抢先重新学习。升级前的在线回合以 `turns.task_id` 识别，历史回填只补新剧情线，不重提取事实、经历、能力或技能使用。导入任务的旧 episode 占位不代表完成结构化抽取，原文仍进入共享管线；服务端逐条校验证据只能来自本批允许学习的来源，不能仅依赖模型遵守提示。

`narrative_extractions.stage` 区分 `claimed` 与 `applied`：声明处理职责不等于完成消费。归档遇到 claimed 来源保留原文并以可重试错误等待；事实、知情、经历、能力及剧情线消费完成后才标为 applied。分叉保留分叉点内待完成声明，由子分支自己的前缀重建完成它，父分支稍后的更新不能替子分支完成。

`scene_json` 保留回合提交时的即时场景投影；生成上下文中的未完成线由当前剧情线版本提供。历史归档描述当时状态，归档中的旧状态不能覆盖当前事实、更正或认知。导演可以读取合法世界资料；模型中的角色仍依靠认知约束和评测遵守信息边界。

## 记录、整理与切换

`plot-thread` 使用稳定线程 ID；`narrative-segment`、`narrative-unit` 保存在 `memory_versions`。`plot_threads` 和 `narrative_units` 是目录，权威正文、来源及依赖仍在现有版本表中。当前管理、可召回、历史证据是不同查询：管理查询可操作候选／暂停技能；召回仍检查状态、版本、来源和能力条件。

局部原文页约 1800 token；摘要上限 600，场景／剧情段 1200，章节 1800。Scene 根据实际转场或最多 8 个内部片段归档；Arc、Chapter 累积至少 5 个闭合子项才检查边界，每批最多 8 个。技术封存不代表剧情转场或目标完成。未闭合边界的否定结果按固定子 ID 缓存，输入未变化时不重复调用。上层引用固定子版本，不循环总结上一版大摘要。

每个片段的加载、模型准备、共用抽取及激活都是持久步骤；每个父归档分别生成。R2 缓冲与 D1 整理游标支持恢复，激活前检查来源、策略、投影和进度版本。新摘要验证成功后才推进覆盖水位；失败保留原文。瞬时错误使用现有最多三次尝试，结构化格式／证据最多两次修复；作者更正过的旧断言跳过写回，其余历史事实可继续回填。

每个整理 Workflow 最多处理 3 个原文或层级归档单元，索引 Workflow 最多处理 2 页（每页 80 条），剩余工作通过持久 outbox 接续到新实例，避免整篇历史耗尽单实例请求配额。无工作检查不消耗单元预算；新计算的否定边界消耗预算并参与续跑键，即使没有新增记忆版本也能继续。索引的清理游标与水位持久保存；资料、授权、删除或版本变化时重新核验，不能按分页缺项删除合法索引。

分支前缀重建每批最多重放 3 个回合，所有批次沿用原重建 ID 及事实抽取幂等键。另存消费者完成水位：事实抽取成功但经历、能力或线程写入失败时，下一次仍补齐该回合。只有这些消费者完成，才推进重建水位；完整前缀重放后独立派发归档，归档后再派发索引，三种工作不叠加在同一个实例里。

`memory_policies` 只有一个分支策略版本。未切换的故事使用合法旧上下文；活跃分支通过一次 outbox 回填构建新模式，所有角色视角达到固定前缀后原子启用。旧任务早于切换目标时只能完成自身整理，不能提前启用。启用后旧 rules／facts／interpretations／narrative 滚动桶不再日常注入，数据库触发器与激活 guard 拒绝迟到旧写入；它们保留作历史审计。迁移不会批量对所有旧故事发起模型调用。

分叉通过现有 lineage、事件上限、记忆 rowid 及授权 rowid 上限确定合法历史；覆盖分叉点之后的归档不能继承。纠正和删除沿依赖图撤销归档／线程，并检查所有分页记录，不局限于管理界面 1000 条。局部重建只读取合法原文或当前子版本，加入有效更正的依赖；重建父项不能使用失效子项。来源 tombstone、epoch 与提交 guard 继续阻止旧任务复活内容。

## 检索与注入

- 中文专名／合法别名映射至实体 ID；同名 ID 保持分开。
- D1 FTS5 v2 保存词频，按名称、标题、关键词、正文加权；查询范围覆盖全部合法历史。旧 FTS 暂保留供迁移前 Worker 使用，它只是一份可重建索引。
- 词法和向量分别取合法候选，授权后 RRF；词法独有命中没有向量相似度门槛。Vectorize 先按分支与视角筛选，再从 manifest 到 D1 检查当前版本；40 个结果不足时有限补取 80、100，复用一次 query embedding。
- 有界关系和时间查询继续参与召回。索引使用版本 ID，按 D1 keyset 页处理所有记录；清理逐个核验旧 manifest，不能因本页缺失删除旧向量。相同记忆的 embedding 跨角色索引缓存复用，缓存批量读取并验证模型和维度。
- `ContextComposer` 统一选择归档、线程和证据。同视角同版本只展开一次，父归档覆盖的子项保留入口；不同认知或时间版本不会因文字相近被合并。技能只展开方法与前提，归档只保存引用和证据入口。
- 只有实际选中的归档覆盖范围才能替代近期长原文；整理游标不是覆盖证明。固定提示词、绑定资料和封存文本保持稳定，动态状态靠后，现有模型缓存 token 日志继续保留。

上下文检查器展示 `selections`、`deduplications`、视角、消费者、历史标记和本次实际原文覆盖区间。归档树按已加载版本展示目录，未加载子项明确提示分页，不假装完整加载整个长篇历史。

## 接口

| 方法与路径（前缀 `/api/v3`）                          | 内容                                                                                      |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `GET /branches/:id/threads?observer=director&after=0` | 当前合法线程，返回稳定 ID、revision ID、状态、完成条件、来源及引用；keyset 分页           |
| `POST /branches/:id/threads`                          | 作者更正当前导演线程；`commandId, expectedHead, memoryId, title, completion, state, text` |
| `GET /branches/:id/archive?observer=director&after=0` | 当前合法归档、层级、子项引用及真实覆盖范围；keyset 分页                                   |
| `POST /branches/:id/archive/rebuild`                  | `commandId, expectedHead, memoryId`，排队重建该局部版本；不学习新经历                     |
| `GET /branches/:id/memory-policy`                     | 本分支策略、版本、构建／启用状态、切换目标                                                |
| `GET /branches/:id/memories/:memoryId/versions`       | 沿用现有版本历史接口                                                                      |

所有读取绑定认证所有者、分支和知情视角。线程更正只接受当前导演视角；角色视角由获取证据维护，界面提示切换导演，不把作者修改自动授权给角色。写入仍使用幂等键、预期剧情版本及数据库内 guard；同一局部重建幂等键不能改指另一节点。恢复与完整备份限制见 [恢复指南](recovery.md)。

## 验证与 embedding 选择

`npm run eval:unified` 执行 8 条中文故事、160 道标准问题及一条连续 5000 回合确定性回放。报告在 [协同评测](../reports/unified-memory-evaluation.json)。这是 SQLite、来源、分支、授权与学习生命周期评测，不能证明自然模型抽取精确率 ≥95%。归档、重复学习、删除、晚到任务、候选补取和完整 SQLite 快照恢复另有回归与浏览器检查。真实模型质量需单独测量。

本轮 [embedding 实测](../reports/embedding-pilot-2026-10-08.json) 使用真实 Workers AI、48 条固定合成语料、20 个问题，内存中做精确 cosine 排序；现有 Vectorize 索引未改动。BGE-M3 的首位命中 95%、MRR .975；Qwen3-0.6B 首位命中 90%、MRR .95，二者 Recall@5/@10 均为 100%。单次查询批次 386／579 ms，不是单请求 p95，也不能代表复杂 RP 大样本。

据此暂保留 BGE-M3。Cloudflare 当前 [Qwen3-0.6B](https://developers.cloudflare.com/workers-ai/models/qwen3-embedding-0.6b/) 与 [BGE-M3](https://developers.cloudflare.com/workers-ai/models/bge-m3/) 同为每百万输入 token $0.0118。`npm run eval:embedding` 输出无调用计划；传 `--run` 后使用显式 Cloudflare 环境凭据进行四次小批量调用并写报告。未来切换模型必须使用独立版本的索引／模型缓存，不能在现有 1024 维索引内混用不同模型向量。
