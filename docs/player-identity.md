# 玩家身份与描写边界

新建故事和输入栏的“设定身份”提供玩家姓名、身份／职业、背景以及描写方式。例如身份可以填写“特雷森学园训练员”，背景可以说明“刚醒来，仍然失忆”。这些是作者给叙事者的资料，不会授予场内角色知情，也不会自动恢复玩家的记忆、授予角色能力或作为玩家已经执行的行为。

默认“自然承接”允许不改变意图和选择的轻微反应，例如“你没动”、保持原姿势和短暂停顿。禁止代写玩家台词、答应／拒绝、同意、情感立场、关键行动和不可逆决定。“严格控制”则不补写这些轻微反应。`global:player-agency` 是项目作者对玩家描写边界的明确细化，仅在这个主题上解释旧指引和世界书中的玩家代理限制，其余规则和证据检查照常有效。叙事和抽取验证使用同一约定；不按错误字符串删除 `violations`，仍然拒绝明确冲突。

`POST /api/v3/branches/:id/player-profile` 接收 `commandId`、`expectedHead` 和 `profile`。身份通过受所有者认证的作者事件保存，提交沿用 D1 CAS、幂等、来源和事务 guard；正在生成时禁止编辑。资料更新推进事件序号，新会话沿用最新版本，历史分叉只能继承当时的身份。重复提交不增加事件；同键不同内容、过期版本和其他所有者请求被拒绝。

身份从当前分支 lineage 前缀内仍有效的原始作者来源读取，不只依赖场景缓存。来源进入上下文 fence；删除源后不会从旧场景、子分支或迟到任务恢复。生成合并新场景时保留作者资料，明确空字符串可以清空字段。身份更新改变剧情版本，已有失败回合应在保存后重新提交原输入；未改变剧情版本时仍可原地重试。

2026-10-08 本地验证：313 项单元／事务测试、TypeScript、生产构建和 128/128 条合成中文回放通过；10/10 浏览器用例通过（本地 Worker 的 local-demo 模式，使用 Chrome）。新增浏览器用例覆盖新故事填写身份、编辑、重新加载、跨会话与分叉，测试未将本地演示解释为真实模型质量验收。

当前 Command Code 直连 `deepseek/deepseek-v4.1-flash` 的三个合成用例经过实际 `analyze` 路径检查。自然停顿曾在首次三次抽取中失败，之后分别经两次结构修复和一次直接抽取成功，均未报告玩家代理冲突；严格停顿一次正确报告 `CANON_CONFLICT`，后续复测一次因 8192 输出上限截断；自然模式下的擅自答应并签约两次均被拒绝。最终一组逐例结果见 `player-agency-live-report.json`，保留截断结果，不将重试通过解释为首次成功率或完整模型质量达标。所有用例是独立合成资料，没有写入用户剧情或将私人开篇放入仓库。
